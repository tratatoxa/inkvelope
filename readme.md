# inkvelope

Письма из блоков. Всё остаётся у вас.

Самодостаточный HTML-конструктор писем для Outlook на Windows и macOS. Работает локально в браузере, не требует сервера и не загружает внешние библиотеки, шрифты или изображения.

Оформление не зависит от корпоративной дизайн-системы: интерфейс использует системные шрифты, письма — стандартные семейства и серо-синюю палитру. Цвета и шрифты письма можно изменить на вкладке «Оформление». Файлы шрифтов в проект не входят.

## Лицензия

Проект распространяется по лицензии MIT — см. `LICENSE`. Его можно использовать, изменять и распространять, в том числе в коммерческих целях, с сохранением уведомления об авторских правах и текста лицензии. Лицензия также включена в `email-builder.html`, чтобы приложение можно было распространять одним файлом.

## Запуск

Откройте `email-builder.html` в современном браузере. Устанавливать зависимости для обычной работы не нужно.

## Основные возможности

- сборка письма из блоков: шапка, изображение, заголовок, текст, список, колонки, кнопка, разделитель, отступ и подпись;
- блок «Колонки»: две или три колонки с картинкой, заголовком, текстом и кнопкой; на узком экране телефона колонки встают друг под другом;
- фон и внутренний отступ у отдельного блока, в том числе на всю ширину письма, и свой цвет текста на фоне;
- кнопка: заливка или только рамка, на всю ширину, скругление углов, цвет надписи и иконка перед текстом;
- прехедер — скрытая строка, которую почта показывает в списке писем рядом с темой;
- перестановка блоков перетаскиванием за ручку `⋮⋮`, перетаскивание новых блоков из палитры в нужное место;
- кнопки ▲▼ у числовых полей: отступы меняются на 4 px, остальные значения на 1, при удержании кнопки — непрерывно;
- «Мои блоки»: сохранение блока кнопкой ★ и всего письма как шаблона, библиотека сохраняется в файл `my-blocks.json` и открывается в других письмах;
- превью в ширину компьютера или телефона (375 px);
- живое превью и редактирование блока по клику на него в письме;
- сброс выделения блока кнопкой «Снять выделение», клавишей `Esc` или кликом по пустому месту письма; режим «Без рамок» скрывает рамки выделения и наведения в превью;
- светлая и тёмная темы интерфейса, переключение кнопкой в правом углу шапки;
- шапка повторяет ход работы над письмом слева направо: импорт, отмена и повтор, экспорт, справка;
- панель «О конструкторе» открыта при запуске: с чего начать, разметка текста, приёмы работы и устройство писем для Outlook;
- отмена изменений кнопкой «Отменить» или сочетанием `Ctrl+Z` / `⌘Z`, повтор — кнопкой «Повторить» или `Ctrl+Shift+Z` / `⌘⇧Z` / `Ctrl+Y`;
- настройка ширины, полей, типографики и цветов письма; отдельный шрифт для заголовков — при импорте он берётся из исходного письма, если заголовки набраны не тем шрифтом, что текст;
- свой шрифт у отдельного блока «Текст» или «Заголовок» — для крупных надписей другим начертанием; заголовок можно выровнять по центру; при импорте такой шрифт и выравнивание берутся из исходного письма;
- стандартные шрифты в списке: Arial, Calibri, Verdana и Georgia; по умолчанию Arial, Helvetica, sans-serif; можно указать свой шрифт со списком запасных;
- проверка ссылок, изображений и типичных проблем совместимости с Outlook, а также предупреждение, если основной шрифт письма не установлен на компьютере и превью показано запасным;
- импорт готовых писем и их перевод в блоки конструктора;
- копирование готового письма, копирование HTML и сохранение `.html`;
- сохранение и открытие проекта в формате JSON.

## Импорт писем

Поддерживаются:

- `.msg` и `.oft` из Outlook для Windows;
- `.eml`, `.mht` и `.mhtml`;
- `.html` и `.htm`;
- `.olk15Message` и `.olk14Message` из Outlook для macOS;
- HTML или обычный текст из буфера обмена на вкладке «Импорт».

Максимальный размер импортируемого файла или проекта — 20 МБ. Проект может содержать до 1000 блоков.

Импорт выполняется локально. Активное содержимое исходного письма удаляется, а внешние картинки и стили не загружаются. Для сохранения изображений используйте письмо со встроенными PNG, JPEG или GIF.

## Работа с изображениями

Изображения встраиваются в проект и письмо как данные. Конструктор не уменьшает их разрешение и не перекодирует PNG в JPEG.

Для хорошей чёткости на экранах с высокой плотностью пикселей исходник рекомендуется готовить в размере 2×. Например, для отображения шириной 600 px нужен исходник шириной около 1200 px. Для текста, схем, интерфейсов и логотипов предпочтителен PNG; для фотографий — качественный JPEG.

Вкладка «Проверка» предупреждает, если картинка растягивается или её разрешения недостаточно для запаса 2×. Большие встроенные изображения увеличивают итоговый размер письма, поэтому перед рассылкой следует проверить лимиты корпоративной почты.

## Мои блоки и шаблоны

Кнопка ★ в карточке блока сохраняет его в «Мои блоки», кнопка «Письмо целиком как шаблон» — всё письмо вместе с оформлением. Блок вставляется кликом или перетаскиванием в список; шаблон заменяет текущее письмо, и это можно отменить.

Библиотека, как и черновик, хранится только в памяти вкладки. Чтобы пользоваться ею в других письмах, сохраните её кнопкой «Сохранить библиотеку (.json)» и откройте файл в следующий раз. При повторном открытии одинаковые записи не дублируются.

## Отправка через Outlook

Основной способ:

1. Нажмите «Копировать письмо».
2. Создайте новое письмо в Outlook.
3. Вставьте содержимое сочетанием `Ctrl+V` или `⌘V`.
4. Отправьте тестовое письмо себе и откройте его в Outlook на Windows и macOS.

Для классического Outlook на Windows можно скачать `.html` и вставить его через «Вставка → Вложить файл → Вставить как текст».

Outlook может отдельно обрабатывать изображения при отправке. Если получатель видит пережатую картинку, сравните исходный файл с изображением, извлечённым из полученного `.eml` или `.msg`.

## Сохранение проекта

Черновик хранится только в памяти текущей вкладки. Чтобы продолжить работу после закрытия или перезагрузки страницы, сохраните проект через «Оформление → Проект → Сохранить проект (.json)».

Старая версия конструктора использовала локальное хранилище браузера. При первом запуске текущая версия пытается восстановить такой черновик в память и затем удалить сохранённую копию.

## Безопасность и автономность

- Content Security Policy запрещает сетевые соединения, внешние ресурсы, плагины и отправку форм;
- разрешены только встроенные изображения PNG, JPEG и GIF;
- превью импортированного письма открывается в изолированном `iframe`;
- скрипты, фреймы, объекты, формы и опасные атрибуты импортированного HTML удаляются;
- внешние изображения, CSS и шрифты не загружаются;
- интеграций с аналитикой, облачными сервисами и API в приложении нет.

Обычные ссылки, добавленные в письмо, сохраняются в итоговом HTML. Переход по ним происходит только после явного действия пользователя в почтовом клиенте или браузере.

## Структура проекта

- `email-builder.html` — приложение целиком: интерфейс, стили, парсеры и генератор письма;
- `changelog.md` — история изменений;
- `update-csp.cjs` — обновление хешей встроенных скриптов в Content Security Policy;
- `tests/offline-check.cjs` — проверка автономности, импорта, экспорта и защиты импорта;
- `tests/undo-check.cjs` — проверка истории изменений;
- `tests/deselect-check.cjs` — проверка сброса выделения и режима «Без рамок»;
- `tests/image-quality-check.cjs` — проверка сохранения исходных байтов изображений;
- `tests/features-check.cjs` — проверка колонок, фона блока, кнопки, прехедера, повтора, кнопок ▲▼, перетаскивания и библиотеки блоков;
- `tests/version-check.cjs` — проверка совпадения версии в приложении и `changelog.md`.

## Разработка

После любого изменения содержимого встроенных `<script>` обновите хеши CSP:

```bash
node update-csp.cjs
node update-csp.cjs --check
```

Для браузерных тестов нужны Node.js, Playwright и Chromium или Google Chrome. Если Playwright и Chrome находятся не в стандартных местах, передайте пути через переменные окружения:

```bash
PLAYWRIGHT_MODULE=/path/to/playwright \
CHROME_PATH="/path/to/Google Chrome" \
node tests/offline-check.cjs

PLAYWRIGHT_MODULE=/path/to/playwright \
CHROME_PATH="/path/to/Google Chrome" \
node tests/undo-check.cjs

PLAYWRIGHT_MODULE=/path/to/playwright \
CHROME_PATH="/path/to/Google Chrome" \
node tests/deselect-check.cjs

PLAYWRIGHT_MODULE=/path/to/playwright \
CHROME_PATH="/path/to/Google Chrome" \
node tests/image-quality-check.cjs

PLAYWRIGHT_MODULE=/path/to/playwright \
CHROME_PATH="/path/to/Google Chrome" \
node tests/features-check.cjs

PLAYWRIGHT_MODULE=/path/to/playwright \
CHROME_PATH="/path/to/Google Chrome" \
node tests/import-layout-check.cjs

PLAYWRIGHT_MODULE=/path/to/playwright \
CHROME_PATH="/path/to/Google Chrome" \
node tests/font-check.cjs
```

Тесты перехватывают обращения страницы к сети и завершаются ошибкой, если приложение пытается обратиться наружу.

## Ограничения

- автоматического сохранения черновика и библиотеки блоков нет;
- Outlook для Windows не понимает скругление углов и медиазапросы: кнопки там прямоугольные, а колонки всегда стоят рядом;
- внешние изображения намеренно не поддерживаются;
- импорт восстанавливает структуру письма эвристически, поэтому после перевёрстки нужно проверить заголовки, списки и подпись;
- `.olk15Message` обычно не содержит сами картинки — для полного импорта лучше экспортировать письмо из Outlook как `.eml`;
- отображение следует проверять тестовой отправкой: версии Outlook используют разные движки рендеринга.
